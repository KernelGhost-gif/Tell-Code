# Tell Engineering Audit

Audit baseline: repository `main` as inspected on 2026-11-02. This document distinguishes inspected source from advertised or aspirational behavior.

## Current architecture

- The Go runtime is a self-contained executable. Its `native/internal/tell/tell.go` contains a line-oriented statement parser, regex-based statement recognition, a hand-written expression lexer/parser/evaluator, built-ins, and standard-library adapters in one package/file.
- The Python runtime in `tell/interpreter.py` has a separate line-oriented statement parser plus a Tell expression lexer/Pratt parser. A restricted Python-AST fallback remains for legacy Python-compatible expression constructs not yet in the shared grammar; it does not call Python `eval`.
- Both runtimes support a small overlapping core: variables, arithmetic, branches, loops, functions, lists and dictionaries, I/O, file operations, basic error handling, interpolation, and selected library calls. Their implementations and edge behavior are independent.
- The command-line interfaces support source files, `run`, `check`, `test`, `format`, `build`, stdin, version display, and a persistent multiline REPL with help/clear/exit commands. The REPL echoes bare expression results and stores the latest result as `_`. The Go CLI has an initial bytecode compiler/VM for a documented subset. History, completion, syntax highlighting, project commands, debugger, and broad language compilation remain unimplemented.
- The repository contains unit tests for both runtimes and six checked-in cross-compiled binaries. CI runs both unit suites and cross-builds binaries on Linux. Native smoke execution is verified here on Windows amd64; CI does not yet execute on all six target OS/architectures.

## Verified gaps and risks

Block headers use explicit prefix and delimiter parsing in both runtimes, including otherwise-if chains. Common assignment, output, return, call, object, I/O, module, library, collection, and error statements use explicit prefix/delimiter parsing. Some statement paths still fall through to legacy regular-expression recognizers, and block parsing remains line-oriented.

1. A provisional core grammar/specification and shared conformance corpus now exist. They cover a small subset and compare output plus selected error-message fragments, but not process exit codes or full diagnostic parity.
2. Block parsing is line-oriented, and residual statement recognition still uses regular expressions. Common statements use a quote- and nesting-aware delimiter scanner. Both runtimes now parse common expressions with dedicated lexers and Pratt parsers. Python still has a restricted host-AST compatibility fallback. Prefix phrases such as `the length of` and `the result of` are still lowered before parsing, and the grammars are not fully equivalent. Go token locations are recorded after some prefix rewrites, so columns can differ from the original source when a phrase expands.
3. Both runtimes now accept Unicode letters and numbers in identifiers across statements and expressions. Combining marks are not accepted; Python and Go still have different Unicode tables and many other syntax and semantic differences.
4. Current control-flow syntax has `if/otherwise`, `while`, `repeat`, and `for each`. Classes support constructors, fields, instance methods, single inheritance, and overriding. Local `.tell` modules support public exports, per-interpreter caching, and circular-import detection. Primitive and user-class runtime annotations and immutable bindings now exist. The native compiler performs conservative static checks for known annotation types; whole-program static typing, generics, static members, access modifiers, multiple inheritance, async tasks, and package management remain absent.
5. Python permits attribute lookup on host values except names starting with `_`; Tell class/instance internals are explicitly hidden, but this is not a security sandbox. Both runtimes allow Tell programs to access the filesystem. Function depth and loop iterations are configurable, but memory and wall-clock use remain unbounded.
6. Runtime errors include filename, statement line, and statement-start column. Parser errors still vary in detail and are not consistently attached to source spans; source excerpts, stable error categories, and call stacks are absent. Some interpolation errors are swallowed to preserve literal braces.
7. Cross-runtime behavior can still diverge in collection operations, truthiness, built-ins, errors, standard-library APIs, and edge cases. Both implementations run the shared corpus against common expected output/error fragments, but the corpus is limited and does not launch both CLIs for direct process-level comparison.
8. The README distinguishes the implemented basic class subset from object-system features still planned. Six-target cross-compilation is not proof of successful execution on all six platforms.
9. The release build script now stages outputs and replaces named artifacts only after all six builds and checksums succeed. The tag-triggered release workflow has been added but has not yet been exercised on GitHub.

- Go test suite: passes on the locally installed Go 1.27.3 toolchain; `go vet ./...` reports no findings.
- All six target binaries cross-compile. The Windows amd64 binary was executed and ran `examples/hello.tell` successfully. Other target binaries were only cross-compiled, not run on their target operating systems.
- Both CLIs were smoke-tested with persistent variables, multiline function definitions, and stdin execution; the native Windows binary runs without Python. The native REPL retains interpreter state through the new public `Session` API.
- Both runtimes default to a 64-level Tell function-call limit; tests confirm runaway recursion returns a Tell error rather than exhausting the host stack.
- Function-call and loop limits can be configured through both runtime APIs and CLIs; tests cover custom low limits, including function depth and repeat count.
- The shared conformance corpus covers otherwise-if chains, precedence, right-associative exponentiation, scientific notation, boolean short-circuiting, portable scalar rendering, Unicode identifiers, named function/constructor/method arguments, class instances, constructors, fields, bound methods, inherited constructors, method overriding, and cached local module imports in both runtimes. Both runtimes reject circular imports.
- The shared corpus also covers delimiter words inside quoted strings and function-call arguments, numeric type names, nested collection formatting, and a division-by-zero error. Both runtimes now skip delimiters found inside strings or nested expressions.
- Python's common expression path now uses its own Tell lexer, Pratt parser, and expression nodes instead of rewriting operator phrases as Python source. Portable number/type names and nested collection display match the native runtime in shared cases. Legacy Python-only expressions use a restricted AST fallback pending common-language support.
- Both runtimes support `Let constant name be ...` and `Let name as TYPE be ...`, with runtime validation for built-in types and declared Tell classes. Shared cases cover reassignment errors, unknown annotations, and subclasses assigned to base-class annotations. Those runtime annotations do not constitute whole-program static typing; the native compiler now adds a separate conservative check for statically obvious cases.
- Both CLIs now provide `format`; it validates source and normalizes indentation without changing program output. `format --check` detects drift. The REPL echoes bare expression results, supports `_` for the last result, and has persistent state. Go and Python tests cover these behaviors; CLI smoke checks passed on the Windows native binary.
- All six release binaries were rebuilt after the CLI updates and their SHA256 entries verified. The Windows amd64 artifact passed version, formatter, REPL, and example-run smoke checks; the remaining targets were cross-compiled only.
- The Go expression parser fuzz target completed a 3-second run with 11,637 executions and no panic. The six release binaries, README, and SHA256SUMS were rebuilt; all checksum entries were verified, and the Windows amd64 release binary ran the language-core example.
- The six configured GOOS/GOARCH targets cross-compiled locally after the latest parser changes. The Windows amd64 executable ran `examples/language-core.tell`; other target binaries were not run on their target operating systems.
- `go test -race ./...` could not run because race instrumentation on Windows requires cgo and no C compiler is installed.
- Python compileall and `git diff --check` pass.
- Native bytecode compiler tests pass for arithmetic, declarations, assignment, output, conditionals, `while`/`repeat`/`for each` loops, loop break/continue, Unicode text iteration, recursive functions, named arguments, lexical closures, constructors, fields, bound methods, single inheritance, overrides, runtime class annotations, collections, built-ins, constant folding, unsupported syntax, and malformed artifacts. A control-flow verifier rejects stack underflow and inconsistent branch-join heights. The native CLI built and ran `.tbc` programs on Windows amd64.
- The native `Analyze` API and `tell check --types` conservatively reject known primitive annotation mismatches in initializers and assignments, while deferring unknown/dynamic types. `tell build` runs the same prepass. Tests cover valid annotations, mismatches, case-sensitive user type names, and runtime-local assignment scope.
- All six release targets were rebuilt from the current Go source; the Windows amd64 artifact was smoke-tested, while the other five were cross-compiled only. Every checked-in SHA256 entry was recalculated from the corresponding artifact.
- The native bytecode compiler now recursively embeds local modules. Tests prove transitive imports, per-run caching, private-name filtering, module-scope closure capture, source-independent `.tbc` execution, and compile-time circular-import rejection. A matching module example runs in both source interpreters.
- `Check that expression.` assertions and `tell test` discovery/execution work in both CLIs. Shared conformance, interpreter tests, native bytecode assertions, and CLI tests cover passing and failing expectations, file discovery, hidden-directory exclusion, and exit status.
- Tell 0.3.0 release binaries were rebuilt for all six configured GOOS/GOARCH targets. Windows amd64 smoke checks verified the version string, Tell test discovery, embedded-module bytecode execution, assertion bytecode, and IDLE-style REPL expression output. ## Recommended engineering sequence

1. Grow the shared corpus to cover exit status, files, libraries, scope, malformed input, and numeric edge cases; run it from a single harness against both runtimes.
2. Align the two expression grammars, port Python legacy-only constructs to the shared grammar where they belong, and then remove the Python AST fallback.
3. Split parsing, AST, evaluation, diagnostics, built-ins, and CLI into maintainable modules; attach source spans to tokens and nodes.
4. Extend diagnostics against the parser representation, then add debugger/linter hooks and formatter support for comments and layout edge cases.
5. Add language features only behind a specification and shared tests. A limited local module feature, initial class model, and native-only bytecode subset now exist; static typing, complete-language compilation, async, and package management remain separate projects.
6. Expand security limits and filesystem policy; document that normal execution is not sandboxed.
7. Make release builds staged/reproducible, add native-runner smoke tests, and publish tagged releases with explicit minimum permissions.

## Work completed in this change

The language specification and shared corpus establish a small parity baseline. Both runtimes implement an initial class subset, dedicated expression lexers/Pratt parsers, immutable bindings, runtime type annotations, and `Check that` assertions; Python retains a restricted legacy AST fallback. Go also handles dictionary literal colons and Python-style list/text slicing. Both CLIs provide an indentation formatter, a persistent REPL that echoes expressions and retains state, and a `test` command that discovers Tell test files. Common sentence parsing uses quote- and nesting-aware delimiters. The native Go CLI compiles a documented subset to versioned JSON stack bytecode and executes it in a VM, including assertions, conditionals, while/repeat/for-each loops, nested control flow, basic try/raise handling, recursively embedded local modules, functions, recursion, named arguments, lexical closures, constructors, instance fields/methods, inheritance, and overrides. Safe scalar constant folding, conservative type checks, module-reference validation, and control-flow stack verification are part of that path. Unsupported statements fail compilation. Bytecode tests cover module scope, export filtering, caching, transitive imports, circular-import rejection, assertions, caught runtime/raised errors, and malformed artifacts. Release binaries/checksums are regenerated whenever compiler changes land; only Windows amd64 has been executed locally, and GitHub Actions workflows have been exercised for v0.3.0 and v0.3.1. These improvements do not claim that the requested general-purpose language feature set is implemented. Future feature work should update the specification and corpus alongside the code.

## CSV standard-library milestone

Tell 0.3.1 adds an explicit `csv` module to both runtimes. `csv.parse(text)` returns rows of text cells; `csv.stringify(rows)` validates list-of-list text input and emits LF-terminated CSV. Shared conformance programs cover quoting, commas, parse/stringify behavior, and invalid cell types. The v0.3.1 tag workflow passed; Windows amd64 ran locally, and five other targets were cross-compiled.

Tell 0.3.2 adds eager `map`, `filter`, and `reduce` built-ins to both runtimes and the native bytecode VM. They accept Tell functions, support closures, and return predictable list or accumulator values. Shared tests cover transformation results, closure capture, callback validation, and compiled execution. The collection guide documents semantics and explicitly lists collection features that remain unimplemented.

The local v0.3.2 work also adds atomic list-based multiple assignment to both interpreters and the native bytecode VM, with shared arity/type/constant checks. Local v0.3.3 adds native `tell new` and `tell init` project scaffolding that creates a runnable source file, an executable smoke test, and a minimal manifest while refusing to overwrite existing files. At that checkpoint, publication was deferred; later v0.3.4 release assets included the accumulated code. Python and Go suites pass, all six v0.3.3 targets build with verified checksums, and Windows amd64 smoke tests exercised the generated project and test command.


## Local v0.3.4 implementation checkpoint

Both source runtimes and the native bytecode VM support call-time default expressions, including constructor defaults, and one final variadic parameter declared with `all remaining values as name`. Defaults evaluate in the function's local scope in parameter order. Both runtimes expose eager `enumerate(list)` pairs, and `For each` can destructure those pairs into multiple loop variables with checked item arity. The shared conformance corpus and bytecode tests cover defaults, per-call evaluation, variadic binding, empty rest lists, named-rest rejection, enumeration, and destructured loops. This milestone does not change the larger parser, typing, object, package, standard-library, debugging, or concurrency gaps above.

## v0.3.5 Python interoperability and distribution

`Use the Python library called statistics as stats.` imports Python modules in the Python runtime and exposes public module functions through a JSON process bridge in the native Go runtime and bytecode VM. Positional/named calls and JSON-compatible arguments/results are exercised; the native adapter imposes a 30-second call limit. It does not retain Python process state or transfer opaque Python objects. Ordinary Go Tell code still runs without Python. No third-party bridge dependency was added.

Release tooling now generates SPDX 2.3 SBOM metadata alongside six platform binaries and SHA-256 checksums. Local verification passed 37 Python test methods, both Go packages, `go vet`, six cross-compiles, and Windows AMD64 source/bytecode interop smoke runs. Only Windows AMD64 executed locally; the other platforms are cross-build verified.
